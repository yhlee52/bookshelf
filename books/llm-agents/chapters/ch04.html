Chapter 04

Instruction tuning과 대화 모델

사전학습을 마친 모델에게 질문을 던지면 답이 아니라 비슷한 질문 목록이 이어질 수 있다. 모델이 한 일은 학습한 대로 그럴듯한 텍스트를 이어 쓴 것뿐이기 때문이다(1.4절). 우리가 쓰는 Claude 같은 대화 모델은 여기에 두 단계를 더 거친다. 사람이 쓴 모범 응답을 따라 쓰게 하는 지도 학습(SFT)과, 사람이 고른 선호를 보상으로 바꿔 모델을 다듬는 선호 학습이다. 이 장은 두 단계의 손실과 목적함수를 세우고, 그 결과물인 system·user·assistant 메시지 형식이 컨텍스트에서 어떻게 쓰이는지 본다. 마지막으로 '선호를 얻는 것'이 '정확한 것'과 어떻게 어긋날 수 있는지 작은 실험으로 확인한다.

  • base model이 질문에 답하지 않고 텍스트를 이어 쓰는 이유와, instruction tuning이 무엇을 바꾸는지 설명할 수 있다.
  • SFT의 마스크 손실과 보상 모델의 Bradley–Terry 손실을 손으로 계산할 수 있다.
  • KL 정규화된 보상 최대화의 최적 정책이 \(\pi_{\text{ref}}\,e^{r/\beta}\)에 비례함을 유도하고 \(\beta\)의 역할을 설명할 수 있다.
  • system·user·assistant 메시지가 하나의 토큰 시퀀스로 직렬화됨을 설명하고, 멀티턴 대화의 입력 토큰이 늘어나는 양을 계산할 수 있다.
  • 보상 모델의 오차와 best-of-N으로 '선호 점수'와 '진짜 품질'이 어긋나는 조건을 설명하고, 이것이 에이전트의 '완료했다'는 말을 믿으면 안 되는 이유와 이어짐을 말할 수 있다.

선수 지식1장(교차 엔트로피, 1.4절의 빈틈), 3장(사전학습, 학습과 in-context 적응의 차이)

base model의 응답과 instruction following

'대한민국의 수도는 어디인가?'라는 텍스트 뒤에 무엇이 올까? 사전학습한 모델은 학습 말뭉치에서 이런 문장 뒤에 흔히 오던 텍스트를 확률로 고른다. 시험 문제 모음이라면 다음 문제가, 게시판이라면 답글이나 광고가, 퀴즈 사이트라면 정답 목록이 이어진다. 질문한 사람이 답을 원한다는 사실은 모델에게 주어진 정보가 아니다. 사전학습만 마친 모델을 base model이라 한다.

우리가 원하는 것은 지시가 요구하는 응답을 내는 모델이다. 이 능력을 instruction following이라 하고, 이를 위해 사전학습한 모델에 추가로 하는 학습을 instruction tuning이라 한다. 3장의 구분으로는 지시 학습은 학습이다. 파라미터가 바뀌며, 새 구조는 없다.

두 연구가 방향을 보였다. Wei 외(2021, FLAN)는 여러 과제를 지시문 형태로 바꿔 미세조정하면 학습에 쓰지 않은 과제에서도 zero-shot 성능이 오른다고 보고했다. Ouyang 외(2022, InstructGPT)는 사람의 시범 응답과 선호 비교를 이용한 세 단계 학습을 제안했고, 초록에서 파라미터가 1.3B인 InstructGPT의 출력이 175B GPT-3의 출력보다 평가자에게 선호된다고 보고했다. 모델 크기를 100배 키우는 것보다 방향을 정해 주는 학습이 더 큰 효과를 낼 수 있다는 뜻이다.

에이전트가 쓰는 모델은 대개 이 단계를 거친다

대화형 모델이 지시를 따르고, 정해진 형식으로 도구를 부르고, 적절한 곳에서 멈추는 행동은 사전학습만으로는 나오기 어렵다. 이런 행동은 이 장의 학습 단계에서 다듬어지는 것으로 알려져 있다. 다만 Claude의 학습 과정은 세부가 공개되어 있지 않으므로, 이 장은 공개된 연구의 일반적인 방법을 설명하며 Claude가 정확히 이렇게 학습되었다고 말하지 않는다.

SFT와 선호 학습

지도 미세조정(SFT)

가장 단순한 방법은 사람이 쓴 (프롬프트, 시범 응답) 쌍으로 학습하는 것이다. 이것을 SFT (supervised fine-tuning)라 한다. 손실은 1장의 교차 엔트로피와 같지만 응답 토큰에만 계산한다. 응답 토큰의 위치 집합을 \(R\)이라 하면 다음과 같다.

\[ L_{\text{SFT}}(\theta)=-\frac1{|R|}\sum_{t\in R}\log p_\theta(x_t\mid x_{\lt t}) \]
프롬프트 토큰은 입력으로만 쓰고 손실에서 뺀다(loss masking).
프롬프트를 마스크하는 이유

프롬프트 4토큰의 \(\log p\)가 각각 \(-2.0\)이고 응답 3토큰의 \(\log p\)가 \(-0.5,-1.2,-0.1\)이라 하자. 응답만 계산하면 \(L=(0.5+1.2+0.1)/3=0.6\)이고, 프롬프트까지 넣으면 \((8.0+1.8)/7=1.4\)이다. 프롬프트까지 넣으면 모델은 사용자의 질문을 그럴듯하게 쓰는 법도 배운다. 지시 학습의 목적은 질문 다음에 응답이 오게 하는 것이므로, 기울기를 응답에만 모은다.

SFT는 구현이 단순하고 효과가 크지만 한계가 있다. 시범 응답을 쓰는 데 사람의 시간이 들고, 모델은 시범을 쓴 사람의 수준을 넘기 어렵다. 또 '허용되는 응답이 여럿일 때 어느 쪽이 더 나은가'를 가르칠 수 없다. 반면 사람은 두 응답을 읽고 어느 쪽이 나은지 고르는 일을 응답을 직접 쓰는 것보다 쉽게 한다. 선호 학습은 이 비교를 이용한다.

보상 모델

같은 프롬프트 \(x\)에 대한 두 응답에서 사람이 \(y_w\)를 \(y_l\)보다 낫다고 골랐다고 하자. 응답에 점수 \(r(x,y)\)를 매기는 보상 모델 (reward model)을 만들려면, 점수의 차이가 선택 확률을 설명하게 하면 된다. 선택 확률을 점수 차이의 시그모이드로 두는 모형이 Bradley–Terry 모형이다.

\[ P(y_w\succ y_l\mid x)=\sigma\bigl(r(x,y_w)-r(x,y_l)\bigr),\qquad \sigma(u)=\frac1{1+e^{-u}} \]

비교 데이터에 대해 이 확률의 음의 로그를 줄이도록 \(r\)을 학습한다.

\[ L_{\text{RM}}=-\log\sigma\bigl(r(x,y_w)-r(x,y_l)\bigr) \]
비교 하나의 손실

\(r(x,y_w)=1.2\), \(r(x,y_l)=0.4\)이면 차이는 0.8이고 \(P=\sigma(0.8)=0.690\), 손실은 \(0.371\)이다. 점수가 거꾸로(\(y_w\)가 0.4, \(y_l\)이 1.2)이면 \(P=0.310\)이고 손실은 \(1.171\)로 커진다. 둘의 점수가 같으면 \(P=0.5\), 손실은 \(\ln2=0.693\)이다. 차이 \(\Delta\)에 대한 기울기는 \(-(1-\sigma(\Delta))\)이므로 틀린 쪽으로 멀수록 \(\Delta\)를 키우는 힘이 세진다.

식 는 점수의 차이에만 달려 있어서 모든 응답의 점수에 같은 수를 더해도 확률이 같다. 보상 점수의 절대 크기에는 의미가 없고, 같은 프롬프트의 응답끼리 비교할 때만 의미가 있다.

보상을 높이되 멀어지지 않기

보상 모델이 있으면 정책(모델) \(\pi\)가 보상이 높은 응답을 내도록 학습할 수 있다. 그런데 보상만 최대화하면 보상 모델의 약점을 파고드는 응답으로 쏠린다(4.4절). 그래서 SFT를 마친 기준 정책 \(\pi_{\text{ref}}\)에서 멀어지는 정도를 KL로 벌한다.

\[ \max_\pi\ \mathbb E_{y\sim\pi(\cdot\mid x)}\bigl[r(x,y)\bigr]-\beta\,D_{\mathrm{KL}}\bigl(\pi(\cdot\mid x)\,\big\|\,\pi_{\text{ref}}(\cdot\mid x)\bigr) \]
\(\beta>0\)이 클수록 \(\pi_{\text{ref}}\)에 가깝게 묶는다.
KL 정규화 목적함수의 최적 정책

식 의 최댓값을 내는 \(\pi\)는 다음과 같다.

\[ \pi^*(y\mid x)=\frac1{Z(x)}\,\pi_{\text{ref}}(y\mid x)\,\exp\!\Bigl(\frac{r(x,y)}\beta\Bigr),\qquad Z(x)=\sum_y\pi_{\text{ref}}(y\mid x)\,e^{r(x,y)/\beta} \]
증명

\(\pi^*\)를 위처럼 정의하면 \(\log\pi^*=\log\pi_{\text{ref}}+r/\beta-\log Z\)이다. 임의의 \(\pi\)에 대해 \(\mathbb E_\pi[r]-\beta D_{\mathrm{KL}}(\pi\|\pi_{\text{ref}})=\mathbb E_\pi\bigl[r-\beta\log\tfrac\pi{\pi_{\text{ref}}}\bigr]=\mathbb E_\pi\bigl[\beta\log\tfrac{\pi^*}{\pi}\bigr]+\beta\log Z=-\beta D_{\mathrm{KL}}(\pi\|\pi^*)+\beta\log Z\)이다. 마지막 식에서 \(\beta\log Z\)는 \(\pi\)와 무관하고 KL은 0 이상이며 \(\pi=\pi^*\)일 때만 0이므로, 목적함수의 최댓값은 \(\pi=\pi^*\)에서 얻는다.

응답이 세 개일 때

\(\pi_{\text{ref}}=(0.5,0.3,0.2)\)이고 보상이 \(r=(0,1,2)\)라 하자. 기준 정책의 기대 보상은 0.7이다. \(\beta=1\)이면 \(\pi^*\propto(0.5,\,0.3e,\,0.2e^2)=(0.5,\,0.816,\,1.478)\)이고 정규화하면 \((0.179,\,0.292,\,0.529)\), 기대 보상은 1.35, \(\pi_{\text{ref}}\)와의 KL은 0.323이다. \(\beta=0.5\)이면 \((0.037,\,0.163,\,0.801)\), 기대 보상 1.76, KL 0.915다. \(\beta=100\)이면 \((0.497,\,0.301,\,0.203)\)으로 \(\pi_{\text{ref}}\)와 거의 같고, \(\beta=0.05\)이면 보상이 가장 큰 응답에 거의 모든 확률이 몰린다.

실제로는 응답 \(y\)가 토큰 시퀀스여서 합을 직접 계산할 수 없고, InstructGPT는 강화학습 알고리즘(PPO)으로 이 목적함수를 근사해서 최적화한다. Rafailov 외(2023, DPO)는 식 를 거꾸로 써서 보상이 \(\beta\log(\pi/\pi_{\text{ref}})\)로 표현됨을 이용해, 보상 모델과 강화학습 없이 비교 데이터에 대한 손실 하나로 같은 목적을 겨냥하는 방법을 제안했다. 선호의 출처도 사람만이 아니다. Bai 외(2022, Constitutional AI)는 사람이 정한 원칙 목록을 바탕으로 AI가 응답을 비교·수정하게 하는 방법을 공개했다. 이 장은 이런 변형들의 차이를 다루지 않는다. 모두 '두 응답 중 낫다고 고른 신호를 모델의 파라미터에 반영한다'는 구조를 공유한다는 점이 이 장에서 중요하다.

system·user 메시지의 역할

대화 모델은 SFT와 선호 학습의 시범과 비교를 모두 대화 형식으로 보며 학습한다. 대화는 역할이 붙은 메시지의 목록이고, 모델은 이 목록을 하나의 토큰 시퀀스로 직렬화해서 읽는다. 1.1절에서 예고한, 차례를 나누는 special token이 여기서 쓰인다. 아래는 설명을 위한 형식이며 특정 모델의 실제 형식이 아니다.

<|system|> 당신은 코드 리뷰를 돕는 도우미다. <|end|>
<|user|> 이 함수의 문제를 알려 줘. <|end|>
<|assistant|> 입력이 비었을 때 오류가 난다. … <|end|>

SFT에서는 식 의 \(R\)이 assistant 메시지의 토큰이다. 모델은 system과 user 메시지를 읽기만 하고 assistant 차례의 토큰을 예측하도록 학습한다. 생성할 때는 직렬화된 대화 끝에 assistant 차례의 시작 표시를 붙이고 1장의 생성 루프를 돌린다. 끝 표시가 나오면 한 차례가 끝난다.

역할은 학습된 약속이다

  • system: 대화 전체에 걸친 지시, 역할, 규칙을 둔다. Claude API에서는 messages와 별도의 system 매개변수로 넘긴다.
  • user: 사용자의 요청이다. 에이전트에서는 도구의 실행 결과도 다음 요청의 user 메시지 안에 tool_result 블록으로 담아 돌려보낸다(tool use 문서, 2026년 11월 확인).
  • assistant: 모델이 낸 이전 차례다. 대화 기록으로 다시 넣을 때 쓴다.

2장에서 보았듯 attention은 컨텍스트의 모든 위치를 같은 방식으로 비교하고, 어느 부분이 '지시'이고 어느 부분이 '데이터'인지 가르는 장치가 없다. 역할 표시가 모델 동작에 영향을 주는 것은 학습이 그렇게 가르쳤기 때문이다. 모델은 system 지시를 user 요청보다 더 따르도록 학습되지만, 이것은 확률적인 경향이지 강제되는 규칙이 아니다. 이를 더 분명하게 가르치려는 연구도 있다(Wallace 외, instruction hierarchy). 도구 결과나 웹 페이지 속에 지시처럼 보이는 문장이 있을 때 모델이 어느 쪽을 따를지는 이 학습에 달려 있고, 그래서 prompt injection이 문제가 된다(24장).

매번 전체 대화를 다시 보낸다

Claude의 Messages API 문서는 이 API가 stateless라서 매번 전체 대화 기록을 보내야 한다고 설명한다(2026년 11월 확인). 모델은 호출과 호출 사이에 아무것도 기억하지 못하고, 이전 대화는 호출자가 다시 넣어 준 컨텍스트로만 존재한다(3.4절). 그러면 대화가 길어질수록 입력이 어떻게 늘어날까? 첫 호출의 입력이 system 500토큰과 user 메시지 300토큰이고, 이후 호출마다 앞의 응답과 새 user 메시지를 합쳐 입력이 300토큰씩 늘어난다고 가정하자.

에이전트의 한 걸음은 한 번의 호출이다

에이전트 루프는 도구를 한 번 부를 때마다 모델을 새로 호출한다(14장). 매 호출에 system 지시와 앞의 대화, 도구 결과가 다시 들어가므로, 위 표는 에이전트의 비용 곡선이기도 하다. 무엇을 컨텍스트에 남기고 무엇을 요약하거나 버릴지는 20장에서 다룬다.

유용함과 정확함의 차이

지금까지의 학습 신호는 모두 사람의 판단에서 온다. 시범 응답을 쓰는 사람과 두 응답 중 낫다고 고르는 사람이다. 그런데 사람이 '낫다'고 고르는 것과 '정확하다'는 것은 같지 않다. 평가자는 답이 맞는지 검증할 시간이나 지식이 없을 수 있고, 그러면 자신 있고, 길고, 질문자의 생각에 맞장구치는 응답에 끌릴 수 있다. Sharma 외(2023)는 여러 AI 비서가 사용자의 견해에 맞춰 답을 바꾸는 아첨(sycophancy) 경향을 보였고, 사람의 선호 비교 데이터와 이를 학습한 보상 모델이 일부 경우에 아첨하는 응답을 정확한 응답보다 더 선호한다고 보고했다.

보상 모델은 이런 사람의 선호를 근사한 대리 지표(proxy)이므로, 진짜 목적과 어긋나는 부분이 있다. 대리 지표를 세게 최적화할수록 어긋난 부분을 파고든다. 이를 reward overoptimization이라 한다(Goodhart의 법칙과 같은 현상). Gao 외(2022)는 보상 모델에 대한 최적화를 강하게 할수록 보상 모델의 점수는 계속 오르지만, 더 믿을 만한 기준으로 잰 점수는 어느 지점에서부터 오히려 내려간다고 보고했다.

이 현상을 가장 단순하게 볼 수 있는 방법이 best-of-N이다. 프롬프트마다 응답을 \(N\)개 뽑아 보상 모델이 가장 높게 준 응답을 고른다. \(N\)이 클수록 대리 지표에 대한 최적화가 세다. 진짜 품질을 \(t\), 보상 모델의 점수를 \(p=t+e\)(\(e\)는 오차)라 하고, \(t\)가 \(\mathcal N(0,1)\)이며 오차도 \(\mathcal N(0,\sigma_e^2)\)일 때를 계산해 보자.

가우스 오차에서 best-of-N의 진짜 품질

\(\sigma_p^2=1+\sigma_e^2\)이고 \(m_N\)을 표준정규분포 \(N\)개의 최댓값의 기댓값이라 하면, 점수가 가장 높은 응답의 진짜 품질의 기댓값은 다음과 같다.

\[ E\bigl[t_{\text{선택}}\bigr]=\frac{m_N}{\sigma_p},\qquad E\bigl[p_{\text{선택}}\bigr]=\sigma_p\,m_N \]
증명

\((t,p)\)가 결합 가우스이므로 \(E[t\mid p]=\frac{\mathrm{Cov}(t,p)}{\sigma_p^2}p=\frac{p}{\sigma_p^2}\)이다. 선택은 \(p\)의 값에만 달려 있으므로 \(E[t_{\text{선택}}]=E\bigl[\frac{p_{\text{선택}}}{\sigma_p^2}\bigr]\)이다. \(p\)는 \(\mathcal N(0,\sigma_p^2)\)을 따르는 값 \(N\)개이므로 그 최댓값의 기댓값은 \(\sigma_pm_N\)이다. 따라서 \(E[t_{\text{선택}}]=m_N/\sigma_p\)이다.

\(m_N\)은 \(N\)이 커질수록 \(\sqrt{2\ln N}\) 정도로 천천히 늘어난다. 곧 오차가 가우스이면 진짜 품질도 계속 오르지만 증가폭이 점점 줄어든다. 그런데 오차가 가우스가 아니라 극단값이 자주 나오는 heavy-tailed 분포라면 어떨까? \(N\)이 커질수록 점수의 최댓값이 진짜 품질이 아니라 오차의 극단값으로 정해질 것이다. 그때는 점수가 아무리 높아도 진짜 품질에 대해 알려 주는 것이 거의 없다.

'완료했습니다'는 대리 지표다

에이전트가 작업이 끝났다고 말하는 것도 모델이 낸 텍스트이고, 이 텍스트가 어떤 응답에 높은 점수를 주는 학습 신호 속에서 다듬어졌다면 '사람이 만족할 만한 말투'일 가능성이 있다. 작업이 실제로 끝났는지는 모델의 말이 아니라 테스트 통과, 산출물 확인 같은 모델 바깥의 검사로 확인해야 한다. 이 책의 검증자 분리(26장)와 평가(31장)가 이 원리 위에 서 있다.

실험: 보상 모델이 틀릴 때 best-of-N의 진짜 품질

슬롯에 적어 둔 질문('같은 지시를 base model과 instruction-tuned 모델에 주면 지시 준수율이 어떻게 다른가')은 실제 모델 쌍을 돌려야 답할 수 있어서 이 장에서는 실행하지 않았다. 지어낸 출력을 싣지 않으려는 선택이며, 설계 방법은 에 두었다. 대신 4.4절의 질문을 확인한다. 보상 모델에 오차가 있을 때 best-of-N의 \(N\)을 키우면 진짜 품질은 어떻게 되는가?

실험 설계

항목내용
설정프롬프트 10,000개. 프롬프트마다 후보 응답 \(N\)개의 진짜 품질 \(t\sim\mathcal N(0,1)\). 보상 점수 \(p=t+e\). 오차 \(e\)는 서로 독립이다.
기준 설계\(N=1\): 고르지 않고 후보 하나를 그대로 쓴다. 진짜 품질의 평균은 0이다.
바꾸는 것\(N\in\{1,2,4,8,16,64,256,1024\}\) 하나. 오차의 분포는 두 경우를 따로 본다: 표준정규분포(\(\sigma_e=1\))와 자유도 2인 Student \(t\) 분포(분산이 무한대인 가장 단순한 heavy-tailed 선택이며, 다른 값은 시험하지 않았다).
고정하는 것시드 0, 프롬프트 수, 진짜 품질의 분포
관측값선택된 응답의 진짜 품질 평균(± 표준오차), 보상 점수 평균
예상 (이론에서)가우스 오차에서는 식 에 따라 진짜 품질이 \(m_N/\sqrt2\)로 \(N\)과 함께 계속 오르고 증가폭이 줄어든다. heavy-tailed 오차에서는 선택이 오차의 극단값에 좌우되므로 진짜 품질이 처음에는 오르다가 내려가고 \(N\to\infty\)에서 0(무작위로 고른 것과 같은 수준)으로 간다. 구체적인 정점의 위치는 예상하지 않았다.
예상이 틀렸다고 볼 조건가우스 오차에서 측정값이 이론값에서 표준오차로 설명되지 않을 만큼 벗어나거나, heavy-tailed 오차에서 \(N=1024\)의 진짜 품질이 정점보다 낮아지지 않으면 틀린 것이다.

코드

Python 3.14와 NumPy 2.5.4에서 실행했다. 다른 NumPy 버전에서는 난수 열이 달라 마지막 자리가 바뀔 수 있지만, 이론값과의 차이는 표준오차 안에 머물러야 한다. 가우스 오차 줄 끝의 두 수는 식 의 이론값(진짜 품질 / 보상 점수)이다.

import math
import numpy as np

rng = np.random.default_rng(0)
P = 10000                                     # 프롬프트(과제) 수

def expected_max(N):                          # 표준정규분포 N개의 최댓값의 기댓값 (수치 적분)
    x = np.linspace(-8, 8, 160001)
    Phi = 0.5 * (1 + np.array([math.erf(v / math.sqrt(2)) for v in x]))
    pdf = np.exp(-x ** 2 / 2) / math.sqrt(2 * math.pi)
    return np.trapezoid(N * x * pdf * Phi ** (N - 1), x)

def best_of_n(N, noise):
    t = rng.normal(size=(P, N))               # 후보 응답의 진짜 품질: 평균 0, 표준편차 1
    p = t + noise((P, N))                     # 보상 모델의 점수 = 진짜 품질 + 오차
    pick = p.argmax(axis=1)                   # 점수가 가장 높은 후보를 고른다 (best-of-N)
    i = np.arange(P)
    return t[i, pick], p[i, pick]

noises = {"가우스 오차": lambda s: rng.normal(size=s),
          "heavy-tailed 오차": lambda s: rng.standard_t(2, size=s)}   # 자유도 2: 분산이 무한대
for name, noise in noises.items():
    print(name)
    for N in (1, 2, 4, 8, 16, 64, 256, 1024):
        t, p = best_of_n(N, noise)
        line = f"  N={N:4d}  진짜 품질 {t.mean():6.3f} ± {t.std() / math.sqrt(P):.3f}  보상 점수 {p.mean():7.3f}"
        if name == "가우스 오차":
            m = expected_max(N)
            line += f"   이론: {m / math.sqrt(2):6.3f} / {m * math.sqrt(2):6.3f}"
        print(line)

해석과 한계

  • 가우스 오차에서는 예상대로 증가폭이 줄며 계속 올랐다. 모든 칸이 이론값에서 표준오차의 1.3배 이내다. \(N\)이 16에서 1024로 64배 늘 때 진짜 품질은 1.25에서 2.29로 늘어, 같은 비용으로 얻는 이득이 점점 줄어든다.
  • heavy-tailed 오차에서는 보상 점수는 계속 오르지만 진짜 품질은 내려갔다. 진짜 품질은 \(N=8\sim16\)에서 0.68로 가장 높았고 \(N=1024\)에서 0.113으로, \(N=1\)의 0.012에 가까워졌다. 같은 구간에서 보상 점수는 3.7에서 40.7로 열 배 넘게 올랐다. 점수가 높다는 것이 품질이 높다는 뜻이 아닌 구간이 생긴 것이다. 정점 앞에서는 \(N\)을 키워 얻는 이득이 있었다는 점도 보아야 한다. 최적화를 하지 말라는 결론이 아니라, 어디까지 최적화할지 정해야 한다는 결론이다.
  • 식 의 KL 항은 이 문제를 겨냥한다. \(\pi_{\text{ref}}\)에서 멀어지는 정도를 묶으면 극단값을 파고드는 응답으로 쏠리는 것을 막는다. 실제 모델에서 이런 패턴이 나타남은 Gao 외(2022)가 보고했다. 이 실험은 그 현상을 직접 재현한 것이 아니라 핵심 구조만 떼어 낸 장난감이다.
  • 가정이 현실보다 단순하다. 실제 보상 모델의 오차는 독립인 잡음이 아니라 응답의 길이나 어조 같은 특징과 얽혀 있을 수 있다. 진짜 품질도 정규분포가 아니고, 후보 응답은 서로 독립이 아니며, best-of-N은 실제로 쓰는 강화학습과 다른 최적화다. 이 실험의 수치를 실제 모델의 성능으로 옮길 수 없다. 옮겨지는 것은 구조다. 대리 지표의 오차가 가볍게 분포하면 최적화는 이득이고, 극단값이 있으면 어디선가 이득이 손실로 바뀐다.

핵심 정리

  1. base model은 학습 말뭉치에서 그럴듯한 텍스트를 이어 쓸 뿐 질문에 답해야 한다는 정보를 갖지 않는다. instruction tuning은 구조는 그대로 두고 파라미터를 바꿔 지시에 맞는 응답을 내게 한다.
  2. SFT는 (프롬프트, 시범 응답)에 대해 응답 토큰에만 교차 엔트로피를 계산한다. 프롬프트를 마스크해야 기울기가 응답을 배우는 데 쓰인다.
  3. 보상 모델은 Bradley–Terry 모형 \(P(y_w\succ y_l)=\sigma(r_w-r_l)\)로 비교 데이터에서 학습한다. 점수는 차이만 의미가 있다.
  4. KL 정규화된 보상 최대화의 최적 정책은 \(\pi^*\propto\pi_{\text{ref}}e^{r/\beta}\)이다. \(\beta\)가 크면 \(\pi_{\text{ref}}\)에 가깝고, 작으면 보상이 가장 큰 응답으로 쏠린다.
  5. system·user·assistant 메시지는 special token으로 구분되어 하나의 시퀀스가 된다. 역할은 attention이 강제하는 규칙이 아니라 학습된 약속이어서 확률적으로만 지켜진다.
  6. Messages API는 stateless라 매 호출에 전체 대화를 다시 보낸다. 대화가 길어지면 호출마다 입력이 늘고 처리한 입력의 합은 호출 수에 대해 제곱으로 늘어난다.
  7. 보상 모델은 사람의 선호를 근사한 대리 지표다. 선호는 정확함과 어긋날 수 있고(아첨), 대리 지표를 세게 최적화하면 어긋난 부분을 파고든다.
  8. best-of-N에서 오차가 가우스이면 진짜 품질이 줄어드는 증가폭으로 계속 오르지만, 극단값이 있는 오차에서는 점수가 오르는 동안 진짜 품질이 내려갈 수 있다. 에이전트의 '완료했다'는 말은 이런 대리 지표이므로 모델 바깥의 검사로 확인한다.

확인 퀴즈

1. base model이 질문 뒤에 다른 질문 목록을 이어 쓰기도 하는 이유는?

1장의 목표는 말뭉치에서 이어진 토큰의 확률을 높이는 것이다. 답을 내야 한다는 신호는 사전학습에 없었다.

2. SFT 손실에서 프롬프트 토큰을 제외하는 이유는?

처럼 프롬프트를 포함하면 손실의 큰 몫이 프롬프트를 맞히는 데 쓰인다.

3. 보상 모델이 비교의 두 응답에 같은 점수를 줬을 때 손실 \(-\log\sigma(r_w-r_l)\)은?

차이가 0이면 \(\sigma(0)=0.5\)이고 \(-\log0.5=\ln2\)이다.

4. 식 에서 \(\beta\)를 매우 크게 하면 최적 정책은?

\(\beta\to\infty\)에서 \(e^{r/\beta}\to1\)이므로 \(\pi^*\to\pi_{\text{ref}}\)이다. 보상이 가장 큰 응답으로 쏠리는 것은 \(\beta\to0\)일 때다.

5. system 메시지에 쓴 규칙에 대한 설명으로 알맞은 것은?

역할은 학습된 약속이다. 중요한 제약은 system 지시에만 맡기지 말고 권한 설정 같은 바깥 장치로 건다(24장).

6. best-of-N에서 보상 모델의 오차가 극단값이 나오는 분포일 때 \(N\)을 매우 크게 하면?

선택이 오차의 극단값에 좌우되어 점수가 품질에 대해 알려 주는 것이 줄어든다. 실험에서 \(N=1024\)의 진짜 품질은 0.113이었다.

연습문제

응답 토큰 3개의 \(\log p\)가 \(-0.5,-1.2,-0.1\)이고 프롬프트 토큰 4개가 각각 \(-2.0\)일 때, 응답만 계산한 SFT 손실과 프롬프트까지 포함한 손실을 구하라.

풀이

응답만: \((0.5+1.2+0.1)/3=0.6\). 포함: \((4\times2.0+1.8)/7=9.8/7=1.4\).

보상 모델이 \(r(x,y_w)=0.4\), \(r(x,y_l)=1.2\)를 주었다. 이 비교에 대한 \(P(y_w\succ y_l)\)과 손실을 구하라. 모든 점수에 3을 더하면 어떻게 되는가?

풀이

차이가 \(-0.8\)이므로 \(P=\sigma(-0.8)=0.310\), 손실은 \(-\ln0.310=1.171\)이다. 모든 점수에 3을 더해도 차이가 그대로여서 \(P\)와 손실이 같다. 보상 점수의 절대 크기는 의미가 없다.

\(\pi_{\text{ref}}=(0.5,0.3,0.2)\), \(r=(0,1,2)\), \(\beta=0.5\)일 때 \(\pi^*\)와 기대 보상을 구하라.

풀이

가중치는 \((0.5,\,0.3e^{2},\,0.2e^{4})=(0.5,\,2.217,\,10.920)\)이고 합 13.637로 나누면 \(\pi^*=(0.037,\,0.163,\,0.801)\)이다. 기대 보상은 \(0.163+2\times0.801=1.76\)이다(기준 0.7).

\(\beta\to\infty\)와 \(\beta\to0\)에서 식 의 \(\pi^*\)가 어떻게 되는지 설명하라. 실제 학습에서 \(\beta\)를 너무 작게 잡으면 어떤 문제가 생기는가?

풀이

\(\beta\to\infty\)이면 \(e^{r/\beta}\to1\)이어서 \(\pi^*\to\pi_{\text{ref}}\)이다. \(\beta\to0\)이면 \(r\)이 가장 큰 응답의 가중치가 압도적으로 커져 그 응답에 확률이 모인다(최댓값이 여럿이면 그들이 \(\pi_{\text{ref}}\) 비율로 나눠 가진다). \(\beta\)가 너무 작으면 정책이 보상 모델의 약점을 파고드는 응답으로 쏠려 4.4절의 overoptimization이 나타난다.

첫 호출의 입력이 system 500토큰과 user 300토큰이고 호출마다 입력이 300토큰씩 늘 때, 8번째 호출의 입력 토큰 수와 8번 호출하는 동안 처리한 입력 토큰의 합을 구하라.

풀이

\(k\)번째 호출의 입력은 \(500+300k\)이므로 \(k=8\)에서 2,900토큰이다. 합은 \(\sum_{k=1}^{8}(500+300k)=500\times8+300\times36=4{,}000+10{,}800=14{,}800\)이다.

위 문제에서 앞 호출과 같은 접두부의 계산을 재사용하는 prompt caching이 있다면 8번 호출에서 새로 계산해야 하는 입력 토큰은 대략 얼마인가? (각 호출에서 앞 호출의 입력 전체가 접두부로 재사용된다고 가정)

풀이

첫 호출은 800토큰을 모두 새로 계산하고, 이후 호출은 앞 호출 입력(접두부)을 재사용하므로 새로 계산하는 것은 300토큰씩이다. 합은 \(800+7\times300=2{,}900\)으로, 마지막 호출의 입력 길이와 같다. 캐시가 없을 때의 14,800에 비해 약 1/5이다. 캐시를 읽는 것도 비용이 들고 접두부가 정확히 같아야 하므로 이 값은 최선의 경우다.

\(t\sim\mathcal N(0,1)\), \(e\sim\mathcal N(0,1)\)일 때 의 증명을 따라 \(N=8\)에서 \(E[t_{\text{선택}}]\)를 구하라. (\(m_8\approx1.4236\))

풀이

\(\sigma_p=\sqrt2\)이고 \(E[t\mid p]=p/2\)이다. \(E[p_{\text{선택}}]=\sigma_pm_8=\sqrt2\times1.4236=2.013\)이므로 \(E[t_{\text{선택}}]=2.013/2=1.007\)이다. 실험 표의 1.008과 맞는다.

공개된 모델 가운데 같은 계열의 base model과 instruction-tuned 모델을 골라 '같은 지시에서 지시 준수율이 어떻게 다른가'를 확인하는 실험을 설계하라. 무엇을 고정하고, 어떻게 채점하며, 무엇을 예상으로 적을지 쓰라.

풀이

예시 설계다. 지시: 기계적으로 검사할 수 있는 제약이 있는 지시 50개(예: '정확히 세 문장으로', 'JSON으로만', '특정 단어를 쓰지 말 것'. IFEval이 이런 방식이다). 고정: 같은 지시 집합, 같은 디코딩 설정과 최대 길이(1장), 지시마다 여러 번 반복(시드 고정). 공정한 비교를 위해 base model에는 3장의 few-shot 프롬프트도 따로 시도한다. 채점: 사람이 읽고 정하지 않고 코드로 제약을 검사한다. 관측값: 준수율, 응답이 EOS 토큰으로 끝났는지, 제약과 무관한 이어 쓰기(다음 질문 생성 등)가 나온 비율. 예상은 결과를 보기 전에 적는다. 예: instruction-tuned 모델의 준수율이 더 높고, base model은 zero-shot에서 이어 쓰기가 더 자주 나온다. 틀렸다고 볼 조건도 함께 적는다. 모델 이름과 버전, 실행 날짜를 기록한다.
