Chapter 17

Claude 에이전트의 해부도

4부는 에이전트를 일반 원리로 다뤘다. 모델이 호출을 내고 하네스가 실행해 결과를 컨텍스트에 붙이고, 끝은 선언·검사·한도로 정하고, 세션이 끝나면 컨텍스트는 사라지고 외부 상태만 남는다. 5부는 같은 원리를 실제 에이전트 하나, Claude Code로 다시 본다. 이 장은 그 전체의 지도이다. Claude Code가 모델과 무엇으로 이루어졌는지, 한 라운드에서 누가 무엇을 하는지, 구성요소가 컨텍스트에 언제 올라오는지, 하고 싶은 일을 어디에 두어야 하는지를 묻는다. 18장부터 24장은 이 지도의 칸을 하나씩 채운다. 제품을 다루는 첫 장이므로 원리(정의와 정리)와 제품의 현재 동작(2026년 11월에 공식 문서로 확인한 것)을 문단으로 나누어 쓰고, 실험은 비용이 드는 실행 대신 모델이 없는 작은 하네스와 내 컴퓨터에 이미 쌓인 세션 기록으로 한다.

  • 모델과 하네스를 가르고, 하네스의 네 가지 일(조립, 실행, 통제, 보존)과 구성요소가 모델에 닿는 두 길(읽기 길, 실행 길)을 설명할 수 있다.
  • 라운드 한 바퀴의 단계(조립, 호출, hook, 권한 평가, 실행, 붙임, 끝)와 각 단계를 정하는 쪽(모델, 하네스, 사용자 설정)을 가릴 수 있다.
  • 접두 캐시의 회계식으로 매 요청에 올리는 항목의 비용과 접두를 바꿀 때의 재작성 비용을 계산하고, 세션 기록의 토큰 사용량 세 숫자로 식을 확인할 수 있다.
  • 구성요소를 컨텍스트에 오르는 시점과 결정권으로 분류하고, 하고 싶은 일을 금지, 의무, 선호로 나누어 알맞은 장치에 배치할 수 있다.
  • 항목을 항상 올릴지 필요할 때 읽게 할지의 손익분기를 토큰 비용과 놓칠 위험으로 계산할 수 있다.

선수 지식14장(정의 14.1의 라운드, 정리 14.3의 접두부 캐시), 15장(정의 15.1의 종료 규칙), 16장(정의 16.1의 세션), 13장(정의 13.4의 부작용), 12장(정리 12.2의 희석).

모델과 하네스

이 책의 4부까지는 모델도 하네스도 작게 만들어 썼다. 모델은 작은 공개 가중치 모델이었고 하네스는 몇십 줄의 코드였다. 그래도 얻은 원리는 제품에 그대로 옮겨 갈 수 있다. 이 절은 그 원리를 한 문장으로 모은다. 에이전트의 행동은 모델이 읽는 컨텍스트에서 나오고, 그 컨텍스트와 그 컨텍스트가 닿는 세계는 하네스가 만든다.

Claude Code의 문서는 같은 구분을 쓴다. 에이전트 루프는 추론하는 모델과 행동하는 도구 두 요소로 돌아가고, 'Claude Code is the layer around the model that provides the tools and manages the context the model sees. This surrounding layer is what the term agentic harness refers to'라고 적는다. 문서에서 'Claude chooses'나 'Claude decides'라고 하면 모델이 추론하는 것을 뜻한다고도 밝힌다(How Claude Code works, 2026년 11월 확인). 이 책도 같은 약속을 쓴다. 모델이 고른다고 하면 모델의 출력이고, 하네스가 한다고 하면 코드가 실행된다는 뜻이다.

모델, 하네스, 에이전트

모델 \(M\)은 컨텍스트 \(c\)를 받아 다음 출력(글과 도구 호출)을 내는 함수이다. 가중치는 고정이다. 하네스 \(H\)는 모델을 부르는 사이에 일어나는 모든 코드와 설정이다. 하네스가 하는 일은 네 가지이다.

  1. 조립. 요청마다 컨텍스트 \(c_r\)을 만든다. 시스템 프롬프트, 도구 정의, 지시 파일, 기억, 대화가 여기에 든다.
  2. 실행. 모델이 낸 호출을 도구로 실행하고 결과를 대화에 붙인다.
  3. 통제. 호출을 허용하거나 확인하거나 거부하고, 한도를 둔다.
  4. 보존. 세션 기록과 파일의 체크포인트를 남긴다.

에이전트는 모델, 하네스, 도구, 세계의 묶음 \((M,H,\text{도구},\text{세계})\)이다. 14장의 루프는 이 묶음이 돌아가는 방식이었다.

Claude Code가 이 틀의 어디에 있는지는 문서가 몇 가지로 적는다. 내장 도구는 크게 다섯 범주이다. 파일 조작(읽기, 편집, 새 파일), 검색(패턴으로 파일 찾기, 정규식으로 내용 찾기), 실행(셸 명령, 서버, 테스트, git), 웹(검색, 문서 가져오기), 코드 인텔리전스(편집 뒤의 타입 오류, 정의로 가기; 별도 플러그인이 필요하다). 하위 에이전트를 띄우거나 사용자에게 묻는 도구도 있다. 이 위에 skill, MCP, hook, 하위 에이전트가 '핵심 루프 위의 층'으로 얹힌다. 또 에이전트 루프, 도구, 기능이 터미널, 데스크톱 앱, IDE 확장, 웹, CI 어디에서나 같고 달라지는 것은 코드가 실행되는 곳(내 컴퓨터, Anthropic이 관리하는 VM, 내 컴퓨터를 브라우저로 원격 조종)과 사용자가 보는 방식뿐이라고 쓴다(같은 문서). 그래서 이 책은 환경을 가르지 않고 하나의 해부도를 그린다.

구성요소가 많아 보여도 모델에 닿는 길은 둘뿐이다. 모델은 컨텍스트의 함수이므로 모델의 출력을 바꾸려면 컨텍스트의 글을 바꿔야 한다. 한편 호출이 세계에 미치는 효과는 모델이 정하지 않고 하네스가 실행하면서 정한다. 다음 정리는 이 두 길을 가르고, 그 귀결로 구성요소의 효과를 찾는 규칙을 준다. 디코딩과 도구는 결정적이라 하자. 실제 제품은 샘플링을 쓰므로 '같은 컨텍스트는 같은 출력 분포를 준다'로 읽으면 된다.

구성요소가 모델에 닿는 두 길
  1. 읽기 길. 모델의 다음 출력은 컨텍스트 \(c_r\)의 함수이다. 구성요소가 다음 출력을 바꾸려면 \(c_r\)의 글을 바꿔야 한다. 지시 파일, 기억, skill의 설명, 도구 정의, hook이 돌려준 글, 하네스가 덧붙이는 알림은 모두 이 길로 닿는다.
  2. 실행 길. 호출 \(a\)가 세계에 미치는 효과는 하네스가 실행하면서 정한다. 구성요소가 모델의 출력과 상관없이 효과를 막거나 바꾸려면 실행의 앞이나 뒤에서 일해야 한다. 권한 규칙, 실행 앞의 hook, 샌드박스가 이 길이다. 막힌 사실은 다음 컨텍스트에 도구 결과의 글로 들어가므로 모델은 그것을 읽기 길로 안다.
  3. 같은 컨텍스트, 같은 대본. 두 설정이 모든 라운드에서 같은 컨텍스트를 만들고 같은 도구 결과를 돌려주면 구성요소가 어떻게 다르든 두 대본은 글자까지 같다. 따라서 두 설정의 대본이 처음 갈리는 라운드는 컨텍스트나 도구 결과가 처음 갈리는 라운드이다.
증명

1번과 2번은 정의이다. 모델은 \(c_r\)만 읽고, 도구의 실행은 하네스의 코드이다. 3번: 첫 컨텍스트가 같으면 첫 출력이 같다. 그 출력에 대한 도구 결과가 같으면 다음 컨텍스트가 같다. 귀납으로 모든 라운드의 출력이 같다. 16장 정리 16.1의 1번과 같은 논법이다. 처음 갈리는 라운드의 출력이 다르려면 그 라운드의 입력(컨텍스트나 앞 라운드의 도구 결과)이 달라야 한다.

두 길은 힘이 다르다. 읽기 길은 모델이 글을 읽고 따라야 효과가 난다. 글이 분포를 움직일 뿐 보증은 없다. 실행 길은 모델이 무엇을 내든 하네스가 적용한다. 이 비대칭이 17.3절의 결정권으로 이어진다. 3번은 디버깅 규칙이다. 구성요소를 하나 켜고 껐더니 행동이 달라졌다면, 컨텍스트가 처음 달라진 라운드를 찾으면 효과가 닿은 길이 어느 쪽인지 가릴 수 있다. 모델 내부는 볼 수 없으므로 우리가 관측하는 것은 이 입력과 출력의 열뿐이다.

에이전트 루프 한 바퀴

14장은 라운드를 모델이 호출을 내고 하네스가 실행해 관찰을 붙이는 한 번으로 정의했다. Claude Code는 그 사이에 단계를 더 둔다. 문서는 루프를 세 국면(컨텍스트 모으기, 행동하기, 결과 확인하기)이 섞여 도는 것으로 설명하고(How Claude Code works), Agent SDK 문서는 같은 루프를 다섯 단계로 적는다. 프롬프트와 시스템 프롬프트, 도구 정의, 대화 기록을 받고, 모델이 글이나 도구 호출로 응답하고, 하네스가 도구를 실행해 결과를 돌려주고, 도구 호출이 없는 응답이 나올 때까지 되풀이하고, 마지막에 토큰 사용량과 비용, 세션 ID가 든 결과 메시지를 낸다(How the agent loop works, 2026년 11월 확인). 문서는 모델 호출 한 번과 도구 실행을 합친 한 바퀴를 턴이라 부르고, 도구 호출이 없는 응답이 나오면 루프가 끝난다고 쓴다. 15장의 종료 규칙과 한도(max_turns, max_budget_usd)가 이 끝에 걸린다.

Claude Code의 한 라운드

한 라운드는 다음 단계로 이루어진다. ①에서 ⑦까지 돌고 ①로 돌아가며, 모델의 응답에 호출이 없으면 ②에서 ⑧로 간다.

  1. 조립. 하네스가 요청을 만든다. 시스템 프롬프트와 도구 정의, 프로젝트 컨텍스트(지시 파일, 기억), 지금까지의 대화가 순서대로 든다.
  2. 호출. 모델이 글과 도구 호출을 낸다.
  3. 실행 앞의 hook. 호출마다 사용자가 등록한 hook이 돌아 호출을 막거나, 묻게 하거나, 그대로 두게 할 수 있다.
  4. 권한 평가. deny 규칙, ask 규칙, allow 규칙의 순서로 맞는 첫 규칙이 결과를 정한다. hook이 allow를 내도 deny와 ask 규칙을 넘지 못한다.
  5. 실행. 읽기만 하는 호출은 동시에, 상태를 바꾸는 호출은 차례로 실행한다.
  6. 실행 뒤의 hook. 도구가 성공한 뒤 hook이 돈다.
  7. 붙임. 결과(막혔다면 거절 메시지)를 대화에 붙이고 ①로 간다.
  8. 끝. 호출이 없는 응답이면 끝내기 전에 Stop hook이 돌고, 이 hook이 막으면 대화가 이어진다. 막지 않으면 결과 메시지를 내고 끝난다.

이 단계 순서는 공식 문서의 서술을 모은 것이다. 실행 앞의 hook이 권한 프롬프트보다 먼저 돈다는 것, 규칙은 deny, ask, allow의 순서로 평가되고 맞는 첫 규칙이 결과를 정하며 구체적인 규칙이라고 순서가 바뀌지 않는다는 것, hook의 결정이 deny와 ask 규칙을 우회하지 못한다는 것은 Permissions 문서에 있다. 읽기 전용 도구(Read, Glob, Grep, 읽기 전용으로 표시된 MCP 도구)는 동시에 돌 수 있고 Edit, Write, Bash처럼 상태를 바꾸는 도구는 충돌을 피하려고 차례로 돈다는 것과, 거부된 호출에서는 모델이 거절 메시지를 도구 결과로 받고 대개 다른 방법을 시도하거나 못 한다고 보고한다는 것은 agent loop 문서에 있다. hook의 발동 시점(PreToolUse은 호출 전에 막을 수 있고, PostToolUse는 성공한 뒤에, Stop은 Claude가 응답을 마칠 때)은 Hooks 문서의 표에 있다(모두 2026년 11월 확인).

이 단계들이 비용에 어떻게 드러나는지가 이 절의 나머지이다. 요청은 라운드마다 하나씩 나가고 모델은 요청 사이에 아무것도 기억하지 않으므로 하네스는 매번 전체 컨텍스트를 다시 보낸다. 새 내용은 끝에 붙으므로 요청의 대부분은 직전 요청과 같고, 서버는 요청의 앞부분(접두)이 최근에 처리한 것과 같은 만큼을 다시 계산하지 않고 캐시에서 읽는다. 이 사실은 14장 정리 14.3에서 읽은 토큰 \(h_t\)로 셌다. 여기서는 그 식에 Claude의 사용량 필드와 가격 구조를 붙인다. API는 요청마다 세 숫자를 돌려준다. 캐시에서 읽은 토큰(cache_read_input_tokens), 캐시에 쓴 토큰(cache_creation_input_tokens), 마지막 캐시 지점 뒤라서 둘 다 아닌 토큰(input_tokens)이고, 세 합이 요청의 입력 길이이다(Prompt caching, 2026년 11월 확인).

접두 읽기의 회계

요청 \(r=1,\dots,n\)의 입력을 \(x_r\), 그 길이를 \(L_r\), 응답의 출력 길이를 \(o_r\)라 하자. 요청은 덧붙이기만 한다고 하자. 곧 \(x_{r+1}=x_r\oplus y_r\oplus z_r\)이다(\(y_r\)은 응답 \(r\), \(z_r\)은 새로 붙은 도구 결과). 캐시는 정확한 접두 일치이고 수명 안이다. 요청 \(r\)에서 캐시에서 읽은 토큰을 \(a_r\), 캐시에 쓴 토큰을 \(w_r\), 그 밖의 토큰을 \(t_r\)라 하면 \(L_r=a_r+w_r+t_r\)이다. 입력 가격을 1로 둔 읽기 가격을 \(\pi_r\), 쓰기 가격을 \(\pi_w\)라 한다.

  1. 읽기의 범위. \(a_r+w_r\le a_{r+1}\le L_r+o_r\).
  2. 이상적인 경우. 응답의 출력과 꼬리 \(t_r\)이 캐시에 오르지 않고 \(t_r=0\)이면 \(a_{r+1}=L_r\), 곧 요청은 직전 요청 전체를 읽고 새 부분 \(L_{r+1}-L_r\)만 쓴다.
  3. 합. 2번의 경우 쓴 토큰의 합은 \(L_n\), 읽은 토큰의 합은 \(\sum_{r\lt n}L_r\)이고 입력 비용은 \(\pi_wL_n+\pi_r\sum_{r\lt n}L_r\)이다. 캐시 없이는 \(\sum_rL_r\)이다.
  4. 항상 올리는 항목. 첫 요청부터 모든 요청에 들어 있는 \(s\)토큰은 입력 비용을 \(s\,(\pi_w+(n-1)\pi_r)\)만큼 늘린다.
  5. 접두의 변경. 요청 \(r\)에서 위치 \(j\)의 토큰이 바뀌고 그 뒤로 유지되면 \(j\) 뒤는 읽지 못하고 다시 쓰며, 비용이 바뀌지 않았을 때보다 \((L_{r-1}-j)(\pi_w-\pi_r)\)만큼 더 든다. \(j\ge L_{r-1}\)이면 0이다. 끝에 덧붙이는 것은 공짜이고 앞쪽을 바꾸는 것이 비싸다.
증명

1번: 요청 \(r\)이 쓴 캐시는 \(x_r\)의 앞 \(a_r+w_r\)토큰을 덮고 수명 안이므로, \(x_{r+1}\)이 \(x_r\)로 시작하는 한 적어도 그만큼을 읽는다. 위쪽: 캐시에 있는 것은 이미 보낸 요청과 생성한 응답의 접두뿐이다. \(x_{r+1}\)과 가장 길게 겹치는 것은 \(x_r\oplus y_r\)이고 \(z_r\)은 새것이므로 겹침은 \(L_r+o_r\) 이하이다. 2번: \(a_r=L_{r-1}\)이고 \(w_r=L_r-L_{r-1}\)이다. 3번: \(w_r\)을 \(r\)에 대해 합하면 망원급수로 \(L_n\)이다. 읽기는 \(a_r=L_{r-1}\)의 합이다. 4번: \(s\)토큰이 \(x_1\)의 앞부분에 있으면 첫 요청에서 한 번 쓰이고(\(\pi_ws\)) 뒤의 \(n-1\)번의 요청에서 읽힌다(\((n-1)\pi_rs\)). 나머지는 항목이 없을 때와 같다. 5번: 요청 \(r\)은 \(j\)까지만 읽고 \(L_r-j\)를 쓴다. 바뀌지 않았다면 \(L_{r-1}\)을 읽고 \(L_r-L_{r-1}\)을 썼을 것이다. \(L_{r-1}-j\)토큰이 읽기에서 쓰기로 옮겨 가므로 차는 \((L_{r-1}-j)(\pi_w-\pi_r)\)이다. 이후 요청은 바뀐 접두가 캐시에 올라 있어 같다.

14장의 식과 이어 보면 \(h_t\)가 여기서는 읽은 토큰 \(a_r\)이고, 새로 계산하는 토큰 \(n_t-h_t\)가 \(w_r+t_r\)이다. 이 정리가 더하는 것은 두 가지이다. 쓰기가 읽기보다 비싸서(\(\pi_w\gt\pi_r\)) 접두가 깨지는 것의 값이 길이만이 아니라 가격 차(\(\pi_w-\pi_r\))로 정해진다는 것, 그리고 \(a_r\), \(w_r\), \(t_r\)가 기록에서 그대로 읽히는 숫자라서 식을 실제 세션으로 확인할 수 있다는 것이다. 1번의 위쪽 경계가 \(L_r\)이 아니라 \(L_r+o_r\)인 까닭은 이 장의 실험에서 드러났다(실험 절의 '실행 전에 본 것'과 '사후 분석').

결정권

구성요소가 컨텍스트에 오르거나 실행에 끼어드는 사건마다 세 가지를 가른다. 발동은 그 사건을 누가 일으키는가이다. 하네스이면 규칙이나 이벤트가 정한 대로 자동으로 일어나고, 모델이면 모델의 출력이 정하고, 사용자이면 명령이나 설정이 정한다. 내용은 무엇이 오르거나 실행되는가이다. 따름은 모델이 그 내용에 따라야 효과가 나는가이다. 따름이 필요한 것은 읽기 길의 구성요소뿐이다().

같은 구성요소도 사건마다 결정권이 다르다. skill의 설명을 올리는 것은 하네스이지만 본문을 올릴지는 모델이 설명을 보고 정하거나 사용자가 이름을 쳐서 정한다. 하위 에이전트를 띄우는 것은 모델이 설명을 보고 정하거나 사용자가 이름을 불러서 정하지만, 띄운 뒤의 실행은 하네스가 한다. hook은 이벤트에서 발동하는 쪽이 하네스이고 안에서 도는 것은 사용자가 쓴 코드이다. 문서는 이 차이를 직접 쓴다. hook은 이벤트에서 Claude가 정하지 않고 발동하므로 결과가 결정적이고, skill은 Claude가 지시를 해석하므로 결과가 달라질 수 있다. CLAUDE.md는 컨텍스트이지 강제 설정이 아니다('Claude treats CLAUDE.md files and auto memory as context. They aren't enforced configuration')(Extend Claude Code, Memory).

결정권을 읽으면 하고 싶은 일이 세 종류로 갈린다. 하지 못하게 하는 일(금지), 반드시 하게 하는 일(의무), 하면 좋은 일(선호)이다. 다음 정리는 각각을 어느 길이 얼마나 보증하는지 센다. 모델의 정책이 컨텍스트의 글을 따를 확률을 \(q\)로 두고 지점마다 독립이라 가정한다. \(q\)는 모델과 글에 달린 값이고 이 장은 재지 않는다.

금지, 의무, 선호
  1. 금지. 실행 길의 장치(deny 규칙, 실행 앞 hook의 deny)가 호출 \(a\)를 막으면, 규칙이 그 호출에 맞는 한 모델의 출력이 무엇이든 \(a\)는 실행되지 않는다. '\(a\)를 하지 마라'는 글만 있으면 \(n\)개의 지점에서 모두 지켜질 확률은 \(q^n\)이다.
  2. 하네스가 대신 할 수 있는 의무(포맷, 린트, 기록). hook이 해당 이벤트마다 실행하므로 모델의 따름이 필요 없다.
  3. 모델의 호출이 필요한 의무. 어떤 장치도 호출을 대신 만들어 주지 못한다. 끝내는 지점에 검사 \(V\)를 두면 미완료를 잡아 끝내기를 막을 수 있고, 한도 \(B\)를 두면 정책이 따르지 않을 때 한도에서 실패로 끝난다. 검사가 없으면 미완료도 '끝났다'로 받아들여진다. 검사는 확인이지 강제가 아니다.
  4. 선호(어조, 관례). 읽기 길뿐이므로 \(q\)가 곧 보증이다.

1번: 실행 길은 모델의 출력 뒤에 있다(의 2번). 규칙이 호출에 맞으면 평가 결과가 deny이고 실행하지 않는다. 모델의 출력이 무엇이든 같다. 글만 있는 경우 지점마다 따를 확률이 \(q\)이고 독립이므로 \(n\)개를 모두 따를 확률은 \(q^n\)이다. 2번: hook은 하네스가 이벤트에서 실행하는 코드이므로 모델의 출력에 달려 있지 않다. 3번: 하네스가 만들 수 있는 것은 자기가 실행하는 코드의 호출이고 모델의 호출은 모델의 출력에서만 나온다. 끝내는 지점의 검사는 상태를 읽어 판정할 뿐 모델의 다음 출력을 정하지 못한다. 검사가 막으면 대화가 이어지고 모델의 정책이 새 컨텍스트(막은 이유)를 읽는다. 그 뒤의 출력은 정책의 몫이므로, 정책이 따르지 않으면 한도 \(B\)까지 되풀이해도 \(V\)는 통과하지 못한다. 4번은 정의이다.

무엇을 어디에 둘까

하고 싶은 일이 생기면 어느 구성요소에 둘지 정해야 한다. 앞 절은 두 가지 기준을 주었다. 정리 17.2는 항목을 컨텍스트에 올리는 비용을, 정리 17.3은 어느 길이 얼마나 보증하는지를 센다. 이 절은 둘을 합쳐 배치의 손익을 계산한다. 두 극단을 비교한다. 항상 올림(지시 파일처럼 모든 요청에 항목 전체가 있다)과 필요할 때 읽음(skill처럼 짧은 설명만 모든 요청에 있고 필요하면 모델이 본문을 불러 대화 끝에 붙인다)이다.

항상 올릴까, 필요할 때 읽게 할까

항목의 크기를 \(s\)토큰, 설명의 크기를 \(d\)토큰(\(d\lt s\)), 세션의 요청 수를 \(n\)이라 하자. 항목이 세션에서 필요할 확률이 \(p\)이고, 필요할 때 본문이 \(k\)번째 요청부터 올라온다고 하자. 모델이 필요한 때 본문을 불러오지 못할 확률을 \(m\), 그때의 손실을 입력 토큰의 비용으로 환산한 값을 \(F\)라 한다. 항상 올리면 불러오는 일의 실패가 없고, 따름의 실패는 두 방식에 같다고 가정한다. 접두 캐시의 가격 \(\pi_w,\pi_r\)을 쓰고(의 4번), \(K_1=\pi_w+(n-1)\pi_r\), \(K_k=\pi_w+(n-k)\pi_r\)로 놓는다.

  1. 비용. 항상 올림은 \(A=s\,K_1\), 필요할 때 읽음은 \(D(p)=d\,K_1+p\,[\,s\,K_k+mF\,]\)이다.
  2. 손익분기. \(A\lt D(p)\)일 필요충분조건은 \(p\gt p^{*}\)이다. 여기서 \[ p^{*}=\frac{(s-d)\,K_1}{s\,K_k+mF}. \]
  3. 토큰만 보면. \(mF=0\)이면 \(p^{*}\ge 1-d/s\)이다. \(d\ll s\)이면 \(p^{*}\)가 1에 가까워서, 항상 올리는 쪽이 싼 경우는 항목이 거의 모든 세션에서 필요할 때뿐이다(\(k\)가 클수록 \(p^{*}\)는 더 크다).
  4. 놓칠 위험. \(mF\gt 0\)이면 \(p^{*}\)가 낮아진다. 항상 올리는 근거는 토큰이 아니라 필요한 때 불러오지 못할 위험이다.
증명

1번: 항상 올림은 의 4번에서 \(s\,K_1\)이다. 필요할 때 읽음은 설명 \(d\)토큰이 항상 올라 있어 \(d\,K_1\)이고, 본문은 확률 \(p\)로 \(k\)번째 요청에서 한 번 쓰이고 남은 \(n-k\)번의 요청에서 읽히므로 \(p\,s\,K_k\)이다. 불러오지 못하는 위험의 기대 손실이 \(p\,mF\)이다. 2번: \(A\lt D(p)\)는 \((s-d)K_1\lt p\,(sK_k+mF)\)와 같고 분모가 양수이다. 3번: \(k\ge1\)이면 \(K_k\le K_1\)이므로 \(p^{*}\ge(s-d)/s\)이다. 4번: \(mF\)가 분모에 더해져 \(p^{*}\)가 작아진다.

1,500토큰짜리 참고 자료는 어디에 둘까

\(s=1500\), \(d=60\), \(n=40\)이고 필요할 때 \(k=5\)번째 요청부터 올라온다고 하자. 가격은 \(\pi_w=1.25\), \(\pi_r=0.05\)이다. 항상 올림의 비용은 \(A=4,800\)이다. 놓칠 위험을 따지지 않으면(\(m=0\)) \(p^{*}=1.024\)로 1보다 크다. 곧 필요할 확률이 1이어도 필요할 때 읽는 쪽이 싸다(\(D(1)=4,692\)). 놓칠 확률이 \(m=0.1\)이고 놓친 손실이 \(F=20000\)토큰어치라면 \(p^{*}=0.709\)이다. 열 번의 세션 가운데 일곱 번을 조금 넘게 필요하면 항상 올리는 쪽이 싸다. 항목이 \(s=6000\), 설명이 \(d=80\)이고 \(n=60\), \(k=10\), \(m=0.05\), \(F=50000\)이면 \(p^{*}=0.995\)로, 거의 모든 세션에서 필요해야 항상 올릴 값이 있다. \(m\)과 \(F\)는 가정한 값이고 이 장이 재지 않았다. 같은 식으로 직접 재야 한다(실험 절의 실험 슬롯 3). E0(f)는 이 식을 4개의 설정과 \(p=0,0.01,\dots,2\)의 201개 점에서 정확한 분수 산술로 확인했고 어긋난 곳은 0개였다.

작은 하네스에서 \(E=3,000\)낱말의 파일을 읽고 그 뒤 요청이 5번 더 이어지는 세션을 두 가지로 돌렸다. 부모 안에서 읽으면 결과가 대화에 붙어 남은 요청마다 읽힌다. 하위 에이전트에 맡기면 \(s=150\)낱말의 요약만 붙는다. 부모의 입력 비용은 4,792.65에서 660.15로 4,132.50만큼 줄었다. 식 \((E-s)(\pi_w+(m'-1)\pi_r)\)와 정확히 같다(\(m'=5\)). 부모의 마지막 요청의 입력 길이는 3,302에서 452토큰으로 줄었다. 그러나 하위 에이전트가 자기 컨텍스트에서 쓴 비용이 4,034.45이다(첫 요청에서 부모의 캐시를 읽지 못했다: 읽은 토큰 0). 두 비용의 합은 4,694.60로 부모 안에서 읽은 비용 4,792.65과 비슷하다. 위임은 비용을 없애지 않고 다른 컨텍스트로 옮긴다. 얻는 것은 부모가 계속 읽는 컨텍스트가 작게 남는 것이다. 이 이득이 압축까지의 간격과 12장의 희석에 어떻게 닿는지는 20장과 22장에서 본다.

자료이 책을 쓴 프로젝트의 세션 기록 9개(닫힌 8개와 이 장을 쓰는 세션의 스냅샷), 응답 2,292개, 전이(연속한 두 응답) 2,283개. Claude Code 2.1.319(7개)와 2.1.327(2개), 모델은 모두 claude-sonnet-5-5. 한 사람의 한 컴퓨터의 기록이므로 독자는 같은 수를 얻지 못한다. 스크립트는 독자의 기록 폴더(~/.claude/projects/ 아래의 프로젝트 폴더)에 그대로 돌릴 수 있다.
개인정보기록에는 대화의 글이 들어 있다. 코드는 글을 출력하지 않고 개수, 글자 수, 토큰 수와 항목 종류의 이름, 캐시 지점의 설정만 낸다. 이메일과 git 상태가 든 항목은 길이만 센다. 세션은 첫 기록 시각의 순서로 S1~S9라 부른다.
바꾸는 것E0: 구성요소(지시 파일의 크기, 접두가 바뀌는 위치와 시점, 규칙, 계획)를 코드에서 바꾼다. E1~E3: 없다(관측만 한다).
고정하는 것가격 배율은 입력 1, 5분 쓰기 1.25, 읽기 0.05이다(Sonnet 5.5의 2026년 11월 가격표). 기록의 분석은 이 기록의 캐시 지점이 모두 1시간 수명이라서 쓰기에 2.0을 쓴다. '낚아챘다'의 기준은 읽은 몫 0.9 미만, 간격의 문턱은 270초이다.
관측값E0: 요청마다 (입력 길이, 읽은 토큰, 쓴 토큰)와 비용, 권한 평가의 결과, 계획에서 실행된 호출의 수. E1: 전이마다 읽은 몫, 직전 읽기·쓰기와의 차, 간격, 압축이 끼었는지. E2: 하네스가 더한 항목의 종류별 개수와 압축 횟수. E3: 첫 호출의 입력 길이와 구성, 사용자 글의 바이트 수.
예산비용이 드는 호출은 없다. GPU를 쓰지 않는다. 실행은 두 파일을 합쳐 몇 초이다.
미리 적은 예상P1(정리 17.2의 1번): 모든 전이에서 읽은 토큰이 직전 요청의 입력 길이 이하이다. P2(문서: 캐시는 비활동 뒤 만료되고, 압축은 대화 층을, 도구와 시스템 정의의 변경은 뒤쪽 전체를 무효로 한다): 읽은 몫 0.9 미만인 전이는 모두 (간격 270초 초과), (압축이 낌), (요청의 모양이나 모델이 바뀜) 가운데 하나 이상이다. O1(관측 가설): 읽은 몫이 0.9 이상인 전이의 95% 이상에서 읽기가 직전 읽기와 직전 쓰기의 합과 정확히 같다. O2(관측 가설): 모든 세션에서 첫 호출의 입력 가운데 사용자 글(바이트 수가 토큰 수의 상한)의 몫이 5% 미만이다. E0은 정확한 항등식이다.
예상이 틀렸다고 볼 조건P1: 위반이 한 전이라도 있으면. P2: 셋 모두 아닌 낚아챔이 하나라도 있으면(역은 예상하지 않는다. 캐시 수명이 길면 긴 간격에도 낚아채지 않을 수 있다). O1: 95% 미만이면. O2: 한 세션이라도 5% 이상이면. 두 번의 실행 출력이 글자까지 같지 않으면 결정성 실패.

코드

코드는 파일 둘이다. tiny17.py는 모델 없이 도는 작은 하네스와 E0의 검산이다(python -I -X utf8 tiny17.py). logs17.py는 세션 기록을 읽는다(python -I -X utf8 logs17.py <기록 폴더>). 실행한 파이썬은 3.14.5이고 두 파일 모두 표준 라이브러리만 쓴다. 전체 코드를 싣는다.

tiny17.py에서 Harness가 컨텍스트의 층을 조립하고(head), 권한을 평가하고(decide), session이 계획을 한 라운드씩 실행하며 요청마다 Cache를 갱신한다. check_all의 (a)~(h)가 정리 17.2~17.4와 그림 17-4의 수를 만든다.

"""tiny17.py — 모델 없이 도는 작은 하네스. 컨텍스트 조립, 접두 캐시 회계, 권한 평가, 결정권의 보장, 배치의 손익분기, 위임의 몫을 헤아린다.
모델은 없다. 모델 자리에는 미리 적어 둔 도구 호출의 열(계획)이 있다. 그래서 이 코드의 수는 Claude의 행동이 아니라 하네스의 계산에 관한 것이다.
python -I -X utf8 tiny17.py      (표준 라이브러리만 쓴다. 출력은 같은 입력에서 글자까지 같다)"""
import itertools, json
from fractions import Fraction as Fr

CW, CR = Fr(5, 4), Fr(1, 20)       # 입력 1.0 기준의 상대 가격: 5분 캐시 쓰기 1.25배, 캐시 읽기 0.05배(Sonnet 5.5, 2026-11 가격표)


def blob(tag, n): return " ".join(f"{tag}{i}" for i in range(n))     # 서로 다른 낱말 n개
def seg(text): return ["<s>"] + text.split()                          # 구획 하나 = 경계 토큰 + 낱말. 토큰 수는 구획마다 더해진다


class Cache:
    """정확한 접두 일치 캐시: 요청의 앞부분이 직전 요청과 같은 만큼만 읽고 나머지는 쓴다."""
    def __init__(self): self.last, self.rows = [], []
    def request(self, toks):
        j = 0
        while j < min(len(toks), len(self.last)) and toks[j] == self.last[j]: j += 1
        self.rows.append((len(toks), j, len(toks) - j)); self.last = list(toks)       # (전체 L, 읽기 cr, 쓰기 cc)
    def cost(self): return sum(CR * cr + CW * cc for _, cr, cc in self.rows)


class Harness:
    def __init__(self, claude_md="", skills=None, mcp=None, defer_mcp=True, hook=None, deny=(), ask=(), allow=()):
        self.claude_md, self.skills, self.mcp, self.defer, self.hook = claude_md, skills or {}, mcp or {}, defer_mcp, hook
        self.deny, self.ask, self.allow = set(deny), set(ask), set(allow)

    def head(self):                       # 대화 앞의 두 층: 시스템 프롬프트·도구 정의 / 프로젝트 컨텍스트. 순서가 접두 캐시를 정한다
        h = [("sys", blob("sys", 120)), ("tools", blob("tool", 80))]
        if not self.defer and self.mcp: h.append(("mcp_schema", " ".join(blob(k, 40) for k in sorted(self.mcp))))
        if self.claude_md: h.append(("claude_md", self.claude_md))
        if self.skills: h.append(("skill_list", " ".join(f"{k} {v[0]}" for k, v in sorted(self.skills.items()))))
        if self.mcp and self.defer: h.append(("mcp_names", " ".join(sorted(self.mcp))))
        return h

    def verdict(self, tool, hook=None):   # 권한 평가: deny, ask, allow 순서이고 hook의 allow는 deny와 ask를 넘지 못한다
        return decide(tool in self.deny, tool in self.ask, tool in self.allow, hook)


def decide(deny, ask, allow, hook):
    if hook == "deny" or deny: return "block"
    if ask or hook == "ask": return "prompt"
    if allow or hook == "allow": return "run"
    return "prompt"                       # 어느 규칙에도 안 걸리면 모드의 기본값(수동 모드에서는 묻는다)


FILES = {"a.py": blob("code", 60), "big.py": blob("big", 3000)}


def session(h, plan, sub=None):
    """계획(도구 호출의 열)을 하네스가 실행한다. 요청마다 접두 캐시를 갱신하고 구획의 이름별 토큰 수를 적는다."""
    convo, cache, seen, log = [("user", "task " + blob("ask", 10))], Cache(), {}, []
    def snap():
        segs = h.head() + convo; toks = [t for _, x in segs for t in seg(x)]
        per = {}
        for lab, x in segs: per[lab] = per.get(lab, 0) + len(seg(x))
        n = len(cache.rows) + 1
        for lab, v in per.items(): seen.setdefault(lab, [n, 0, 0]); seen[lab][1] += 1; seen[lab][2] = v      # 처음 나온 요청, 나온 요청 수, 마지막 크기
        cache.request(toks)
    for tool, arg in plan:
        snap()                                                          # 모델 호출 하나(요청 하나)
        hk = h.hook("pre", tool, arg) if h.hook else None
        v = h.verdict(tool, hk); log.append((tool, arg, v))
        if v == "block": res = "denied " + blob("why", 5)
        elif tool == "skill": convo.append(("skill_body", h.skills[arg][1])); res = "loaded"
        elif tool == "mcp" and h.defer and not any(l == "mcp_schema" for l, _ in convo): convo.append(("mcp_schema", blob(arg, 40))); res = "found"
        elif tool == "agent": res = sub(arg)                            # 하위 에이전트는 자기 컨텍스트에서 돌고 요약만 돌아온다
        else: res = FILES.get(arg, "ok")
        convo += [("assistant", f"call {tool} {arg}"), ("agent_summary" if tool == "agent" else "tool", res)]
        add = h.hook("post", tool, arg) if h.hook else None             # hook이 글을 돌려주면 컨텍스트에 붙고, 안 돌려주면 0토큰이다
        if add: convo.append(("hook_out", add))
    snap()                                                              # 도구 호출 없는 마지막 응답
    return cache, seen, log, convo


def sub_agent(n_read, s):
    """하위 에이전트: 새 컨텍스트에서 큰 파일을 읽고 s낱말의 요약을 돌려준다. 자기 캐시를 따로 쓴다."""
    box = {}
    def run(_arg):
        c, _, _, _ = session(Harness(), [("read", "big.py")]); box["cache"] = c
        return blob("sum", s)
    return run, box


def check_all():
    out = {}
    plan = [("read", "a.py"), ("edit", "a.py"), ("run", "t"), ("read", "a.py"), ("edit", "a.py"), ("run", "t"), ("read", "a.py"), ("run", "t")]

    # (a) 접두 읽기의 회계(정리 17.2의 1): 덧붙이기만 하면 요청 r은 직전 요청 전체를 읽고 새 부분만 쓴다
    c, _, _, _ = session(Harness(), plan); R = c.rows; N = len(R)
    assert R[0][1] == 0 and all(R[r][1] == R[r - 1][0] and R[r][2] == R[r][0] - R[r - 1][0] for r in range(1, N))
    assert sum(cc for _, _, cc in R) == R[-1][0] and c.cost() == CW * R[-1][0] + CR * sum(L for L, _, _ in R[:-1])
    out["a"] = {"requests": N, "L_first": R[0][0], "L_last": R[-1][0], "write_total": sum(cc for _, _, cc in R), "read_total": sum(cr for _, cr, _ in R), "cost": float(c.cost()), "cost_nocache": float(sum(L for L, _, _ in R))}

    # (b) 항상 올리는 항목의 비용(정리 17.2의 3): s낱말의 CLAUDE.md는 모든 요청에 s+1토큰을 더하고 비용을 (s+1)(CW+(N-1)CR) 늘린다
    rows = []
    for s in (50, 200, 1000):
        c2, _, _, _ = session(Harness(claude_md=blob("rule", s)), plan)
        assert all(b[0] - a[0] == s + 1 for a, b in zip(R, c2.rows)) and c2.cost() - c.cost() == (s + 1) * (CW + (N - 1) * CR)
        rows.append({"s": s, "extra_cost": float(c2.cost() - c.cost()), "per_request": s + 1})
    out["b"] = rows

    # (c) 접두가 바뀌는 비용(정리 17.2의 2): 요청 r에서 위치 j의 토큰이 바뀌면 j까지만 읽고, 바뀐 만큼 비싸다 (L_{r-1}-j)(CW-CR)
    cnt = 0
    for r in range(1, N):
        for j in range(0, R[-1][0], 17):
            base = Cache(); chg = Cache()
            toks = [[f"t{i}" for i in range(L)] for L, _, _ in R]
            for q in range(N):
                base.request(toks[q])
                t = list(toks[q])
                if q >= r and j < len(t): t[j] = "X"
                chg.request(t)
            exp = max(0, R[r - 1][0] - j) * (CW - CR)
            assert chg.cost() - base.cost() == exp; cnt += 1
    out["c"] = {"cases": cnt}

    # (d) 권한 평가의 순서: deny, ask, allow. hook의 allow는 deny·ask 규칙을 넘지 못하고 hook의 deny는 항상 막는다
    tab, bad = {}, 0
    for d, a, al, hk in itertools.product((0, 1), (0, 1), (0, 1), (None, "allow", "ask", "deny")):
        v = decide(d, a, al, hk); tab[v] = tab.get(v, 0) + 1
        if d and v != "block": bad += 1
        if hk == "deny" and v != "block": bad += 1
        if a and not d and hk != "deny" and v != "prompt": bad += 1
        if hk == "allow" and (d or a) and v == "run": bad += 1
    assert bad == 0
    out["d"] = {"combos": 32, "verdicts": tab, "violations": bad}

    # (e) 결정권(정리 17.3): 계획이 컨텍스트를 무시하는 최악의 정책이라고 하고 길이 5 이하의 모든 계획을 헤아린다
    alpha = [("read", "a.py"), ("edit", "a.py"), ("run", "t"), ("delete", "prod")]
    plans = [list(p) for n in range(1, 6) for p in itertools.product(alpha, repeat=n)]
    ctx_only = gate = 0
    for p in plans:
        _, _, lg1, _ = session(Harness(claude_md="never delete prod " + blob("rule", 20), allow=("delete",)), p)         # 지시만 있다: 글이 있어도 정책이 무시한다
        _, _, lg2, _ = session(Harness(claude_md="never delete prod " + blob("rule", 20), deny=("delete",)), p)
        ctx_only += sum(1 for t, _, v in lg1 if t == "delete" and v == "run"); gate += sum(1 for t, _, v in lg2 if t == "delete" and v == "run")
    has_del = sum(1 for p in plans if any(t == "delete" for t, _ in p))
    assert gate == 0 and ctx_only == sum(n * 4 ** (n - 1) for n in range(1, 6)) == 1593 and has_del == len(plans) - sum(3 ** n for n in range(1, 6))
    # 의무: Stop 검사 V = '테스트를 돌렸다'. 검사는 미완료를 잡아 끝내기를 막을 뿐이고 무엇을 할지는 정해 주지 못한다.
    # 정책이 지시를 따르면(순응) 한도 B 안에서 통과하고 따르지 않으면(고집) 한도에서 끝난다. 검사가 없으면 두 경우 모두 '끝났다'가 받아들여진다
    B = 3
    ran = sum(1 for p in plans if any(t == "run" for t, _ in p)); missed = len(plans) - ran
    assert missed == sum(3 ** n for n in range(1, 6)) == 363
    out["e"] = {"plans": len(plans), "with_delete": has_del, "ctx_only_exec": ctx_only, "gate_exec": gate, "ran": ran, "missed": missed,
                "no_check_accepted": len(plans), "check_obstinate_pass": ran, "check_obstinate_limit": missed, "check_compliant_pass": len(plans), "budget": B}

    # (f) 배치의 손익분기(정리 17.4): 항상 올림 A와 설명만 올리고 필요할 때 읽음 D(p)
    def cost_A(s, n): return s * (CW + (n - 1) * CR)
    def cost_D(s, d, n, k, p, m, F): return d * (CW + (n - 1) * CR) + p * s * (CW + (n - k) * CR) + p * m * F
    def pstar(s, d, n, k, m, F): return (s - d) * (CW + (n - 1) * CR) / (s * (CW + (n - k) * CR) + m * F)
    grid, worst = [], 0
    for s, d, n, k, m, F in [(1500, 60, 40, 5, Fr(1, 10), 20000), (1500, 60, 40, 5, Fr(0), 0), (400, 40, 12, 3, Fr(1, 5), 8000), (6000, 80, 60, 10, Fr(1, 20), 50000)]:
        ps = pstar(s, d, n, k, m, F)
        for i in range(0, 201):
            p = Fr(i, 100)
            if (cost_A(s, n) < cost_D(s, d, n, k, p, m, F)) != (p > ps): worst += 1
        grid.append({"s": s, "d": d, "n": n, "k": k, "m": float(m), "F": F, "pstar": float(ps), "A": float(cost_A(s, n)), "D1": float(cost_D(s, d, n, k, 1, m, F))})
    assert worst == 0
    out["f"] = {"cases": grid, "mismatch": worst}

    # (g) 위임의 몫: 부모 컨텍스트는 요약만큼만 자란다. 같은 읽기를 부모 안에서 하면 E낱말만큼 자라고 남은 요청마다 읽힌다
    E, s = 3000, 150
    runner, box = sub_agent(E, s)
    p_sub, _, _, conv_sub = session(Harness(), [("agent", "x"), ("read", "a.py"), ("run", "t"), ("run", "t"), ("run", "t")], sub=runner)
    p_in, _, _, conv_in = session(Harness(), [("read", "big.py"), ("read", "a.py"), ("run", "t"), ("run", "t"), ("run", "t")])
    m = len(p_in.rows) - 1                                            # 큰 읽기 뒤의 요청 수
    diff = p_in.cost() - p_sub.cost(); sub_c = box["cache"]
    exp_diff = (E - s) * (CW + (m - 1) * CR)
    assert diff == exp_diff, (diff, exp_diff)
    out["g"] = {"E": E, "s": s, "requests_after": m, "parent_cost_inline": float(p_in.cost()), "parent_cost_delegated": float(p_sub.cost()), "saved": float(diff),
                "sub_cost": float(sub_c.cost()), "sub_first_cr": sub_c.rows[0][1], "parent_last_L_inline": p_in.rows[-1][0], "parent_last_L_delegated": p_sub.rows[-1][0]}

    # (h) 구성요소의 적재 표: 같은 하네스에 모든 구성요소를 켜고 '처음 나온 요청, 나온 요청 수, 마지막 크기'를 적는다
    h = Harness(claude_md=blob("rule", 300), skills={"deploy": (blob("d", 25), blob("body", 800))}, mcp={"db_query": 1, "slack_post": 1},
                hook=lambda ev, t, a: (blob("lint", 40) if (ev == "post" and t == "edit") else None))
    runner2, _ = sub_agent(E, s)
    c3, seen, log, _ = session(h, [("read", "a.py"), ("skill", "deploy"), ("mcp", "db_query"), ("edit", "a.py"), ("run", "t"), ("agent", "x"), ("run", "t")], sub=runner2)

import glob, json, os, re, sys
from collections import Counter
from datetime import datetime

THRESH, GAP = 0.9, 270.0     # 미리 정한 값: '낚아챘다'의 기준(읽은 몫 < 0.9), 5분 수명에서 시각 어긋남 30초를 뺀 문턱(초)
TYPES = ("skill_listing", "instructions", "agent_listing_delta", "mcp_instructions_delta", "deferred_tools_delta", "session_context", "model", "date", "environment")


def tstamp(o): return datetime.fromisoformat(o["timestamp"].replace("Z", "+00:00")).timestamp()


def load(path):
    lines = []
    for raw in open(path, encoding="utf8"):
        try: lines.append(json.loads(raw))
        except ValueError: pass
    return lines


def user_bytes(o):
    c = (o.get("message") or {}).get("content")
    if isinstance(c, str): txt = c
    elif isinstance(c, list): txt = "\n".join(b.get("text", "") for b in c if isinstance(b, dict) and b.get("type") == "text")
    else: txt = ""
    return len(re.sub(r"<system-reminder>.*?</system-reminder>", "", txt, flags=re.S).strip().encode("utf8"))


def analyse(lines):
    resp, order, comps, last_q, nq, ub = {}, [], [], None, 0, []
    for i, o in enumerate(lines):
        t = o.get("type")
        if t == "api-request": last_q = o; nq += 1
        elif t == "system" and o.get("subtype") == "compact_boundary": comps.append(i)
        elif t == "user" and not o.get("isSidechain"):
            m = o.get("message") or {}; c = m.get("content")
            if not (isinstance(c, list) and any(isinstance(b, dict) and b.get("type") == "tool_result" for b in c)): ub.append((i, user_bytes(o)))
        elif t == "assistant" and not o.get("isSidechain"):
            m = o.get("message") or {}; u = m.get("usage")
            if not isinstance(u, dict) or m.get("model") == "<synthetic>": continue
            key = (u["input_tokens"], u["cache_creation_input_tokens"], u["cache_read_input_tokens"])
            mid = m.get("id")
            if mid not in resp:
                q = last_q or {}
                resp[mid] = dict(i0=i, i1=i, t0=tstamp(o), u=key + (u["output_tokens"],), model=m.get("model"), ver=o.get("version"), shape=q.get("shapeHash"),
                                 qmodel=(q.get("params") or {}).get("model"), q=q, nq=nq, incons=0)
                order.append(mid); nq = 0
            else:
                r = resp[mid]; r["i1"] = i; r["incons"] += int(r["u"][:3] != key)
    seq = [resp[k] for k in order]
    trans = []
    for a, b in zip(seq, seq[1:]):
        La, cra, cca, crb = sum(a["u"][:3]), a["u"][2], a["u"][1], b["u"][2]
        gap = b["t0"] - a["t0"]; comp = any(a["i0"] < c < b["i0"] for c in comps); shape = (a["shape"], a["qmodel"]) != (b["shape"], b["qmodel"])
        trans.append(dict(La=La, cr=crb, ratio=crb / La, dev=crb - (cra + cca), gap=gap, comp=comp, shape=shape, ccb=b["u"][1], viol=crb > La, miss=crb < THRESH * La))
    return dict(seq=seq, trans=trans, comps=comps, ub=ub)


def first_sizes(lines, upto):
    """첫 요청 앞에 기록된 하네스 항목의 크기(글자 수). 이메일과 git 상태가 든 session_context는 길이만 센다."""
    sz, seen = {}, set()
    for o in lines[:upto]:
        if o.get("type") != "attachment": continue
        a = o["attachment"]; ty = a.get("type")
        if ty in seen: continue
        seen.add(ty)
        if ty == "skill_listing": sz[ty] = (len(a["content"]), a.get("skillCount"))
        elif ty == "agent_listing_delta": sz[ty] = (sum(len(x) for x in a["addedLines"]), len(a["addedTypes"]))
        elif ty == "mcp_instructions_delta": sz[ty] = (sum(len(x) for x in a["addedBlocks"]), len(a["addedNames"]))
        elif ty == "deferred_tools_delta": sz[ty] = (sum(len(x) for x in a["addedLines"]), len(a["addedNames"]))
        elif ty == "instructions": sz[ty] = (sum(len(f["content"]) for f in a["files"]), len(a["files"]))
        elif ty == "prompt_snapshot": sz[ty] = (sum(len(x) for x in a["systemPrompt"]), len(a["systemPrompt"]))
        elif ty == "session_context": sz[ty] = (sum(len(v) for v in a["context"].values() if isinstance(v, str)), len(a["context"]))
    return sz


def cache_points(q):
    return ";".join("/".join(str(x) for x in c["path"]) + ":" + str(c["value"].get("ttl")) + ":" + str(c["value"].get("scope")) for c in (q.get("cacheControl") or []))


def main(d, outdir=None):
    S = []
    for f in glob.glob(os.path.join(d, "*.jsonl")):
        lines = load(f); ts0 = min(tstamp(o) for o in lines if "timestamp" in o)
        S.append((ts0, lines))
    S.sort(key=lambda x: x[0]); res = {"sessions": [], "misses": []}
    P = print
    P("[1] 기록 개요 (세션은 첫 시각의 순서로 S1, S2, ...)")
    tot = Counter()
    for n, (_, lines) in enumerate(S, 1):
        A = analyse(lines); seq, tr = A["seq"], A["trans"]
        att = Counter(o["attachment"]["type"] for o in lines if o.get("type") == "attachment")
        vers = sorted({r["ver"] for r in seq}); mods = sorted({r["model"] for r in seq})
        inc = sum(r["incons"] for r in seq); one = sum(1 for r in seq if r["nq"] == 1)
        P(f"S{n}: 응답 {len(seq)}, 전이 {len(tr)}, 압축 {len(A['comps'])}, 버전 {','.join(vers)}, 모델 {','.join(mods)}, 한 응답 안의 사용량 불일치 {inc}, 앞 응답 이후 요청이 정확히 1개인 응답 {one}")
        s = dict(id=n, responses=len(seq), transitions=len(tr), compactions=len(A["comps"]), att={k: att.get(k, 0) for k in TYPES}, ver=vers, model=mods, incons=inc)
        # E1
        for t in tr:
            tot["trans"] += 1; tot["viol"] += t["viol"]; tot["intact"] += (not t["miss"]); tot["miss"] += t["miss"]
            if not t["miss"]:
                tot["exact"] += (t["dev"] == 0); tot["dev_small"] += (t["dev"] != 0 and abs(t["dev"]) <= 10); tot["dev_big"] += (abs(t["dev"]) > 10)
            else:
                ex = [k for k, fl in (("gap", t["gap"] > GAP), ("comp", t["comp"]), ("shape", t["shape"])) if fl]
                for k in ex: tot["by_" + k] += 1
                tot["unexplained"] += (not ex)
                res["misses"].append(dict(s=n, ratio=round(t["ratio"], 3), gap=round(t["gap"]), comp=t["comp"], shape=t["shape"], ccb=t["ccb"], expl=ex or ["none"]))
        # E3
        first = seq[0]; L1 = sum(first["u"][:3]); B = sum(b for i, b in A["ub"] if i < first["i0"])
        sz = first_sizes(lines, first["i0"])
        s.update(L1=L1, cr1=first["u"][2], cc1=first["u"][1], in1=first["u"][0], user_bytes=B, user_share_max=B / L1, first_shape=first["shape"][:8] if first["shape"] else None, points=cache_points(first["q"]), sizes=sz)
        res["sessions"].append(s)
    P(); P("[2] 접두 읽기의 회계 (사전 예상 P1, P2, 관측 가설 O1)")
    P(f"전이 {tot['trans']}개. 읽은 토큰이 직전 요청의 길이를 넘은 전이 {tot['viol']}개 (P1 위반)")
    P(f"읽은 몫이 {THRESH} 이상인 전이 {tot['intact']}개: 읽기 = 직전 읽기 + 직전 쓰기를 정확히 만족 {tot['exact']}개, 어긋남 1~10토큰 {tot['dev_small']}개, 11토큰 이상 {tot['dev_big']}개")
    P(f"읽은 몫이 {THRESH} 미만인 전이(낚아챘다) {tot['miss']}개: 간격 {GAP:.0f}초 초과 {tot['by_gap']}개, 압축 끼임 {tot['by_comp']}개, 요청 모양·모델 바뀜 {tot['by_shape']}개 (겹칠 수 있음), 어느 것도 아님 {tot['unexplained']}개")
    for m in res["misses"]: P(f"  S{m['s']}: 읽은 몫 {m['ratio']}, 간격 {m['gap']}초, 압축 {int(m['comp'])}, 모양 바뀜 {int(m['shape'])}, 쓰기 {m['ccb']:,}, 설명 {'+'.join(m['expl'])}")
    P(); P("[3] 하네스가 컨텍스트에 더한 항목의 개수 (압축 횟수 c에 대해 1+c인가)")
    hd = [x for x in TYPES]; P("세션 c " + " ".join(hd))
    for s in res["sessions"]: P(f"S{s['id']} {s['compactions']} " + " ".join(f"{s['att'][k]}" for k in hd))
    ok = {k: sum(1 for s in res["sessions"] if s["att"][k] == 1 + s["compactions"]) for k in hd}; has = {k: sum(1 for s in res["sessions"] if s["att"][k] > 0) for k in hd}
    P("개수가 1+c와 같은 세션 수 / 그 항목이 있는 세션 수: " + ", ".join(f"{k} {ok[k]}/{has[k]}" for k in hd))
    P(); P("[4] 첫 호출 (입력 L = 새로 읽음·캐시 쓰기·캐시 읽기의 합)")
    for s in res["sessions"]:
        P(f"S{s['id']}: L {s['L1']:,} = 읽기 {s['cr1']:,} + 쓰기 {s['cc1']:,} + 그 밖 {s['in1']}, 사용자 글 {s['user_bytes']:,}바이트(토큰 수의 상한), 몫 {s['user_share_max'] * 100:.2f}% 이하, 첫 모양 {s['first_shape']}, 캐시 지점 {s['points']}")
    for s in res["sessions"][:1] + res["sessions"][-1:]:
        P(f"S{s['id']}의 항목 크기(글자 수, 개수): " + ", ".join(f"{k} {v[0]:,}({v[1]})" for k, v in s["sizes"].items()))
    grp = {}
    for s in res["sessions"]: grp.setdefault(s["first_shape"], set()).add(s["cr1"])
    P("첫 모양 해시가 같은 세션끼리 첫 호출의 캐시 읽기가 같은가: " + ", ".join(f"{k}: {sorted(v)}" for k, v in sorted(grp.items(), key=lambda x: str(x[0]))))

    for s in res["sessions"]: cr_map.setdefault(s["cr1"], set()).add(s["first_shape"])

    res["tot"] = dict(tot)
    if outdir: json.dump(res, open(os.path.join(outdir, "out17_logs.json"), "w", encoding="utf8"), ensure_ascii=False, indent=1, sort_keys=True)
    return res

핵심 정리

  1. 모델은 컨텍스트를 읽고 출력을 내는 함수이고 하네스는 모델을 부르는 사이의 모든 코드와 설정이다. 하네스는 조립, 실행, 통제, 보존을 한다(). 구성요소가 모델에 닿는 길은 둘이다. 컨텍스트의 글을 바꾸는 읽기 길은 모델이 따라야 효과가 나고, 실행 앞뒤에서 일하는 실행 길은 모델의 출력과 무관하게 적용된다. 두 설정의 대본이 처음 갈리는 곳은 컨텍스트나 도구 결과가 처음 갈리는 라운드이다().
  2. 한 라운드는 조립, 호출, 실행 앞의 hook, 권한 평가(deny, ask, allow의 순서), 실행, 실행 뒤의 hook, 붙임, 끝(Stop hook)의 단계이다(). 모델이 정하는 것은 호출뿐이고 나머지는 하네스와 사용자 설정이 정한다.
  3. 접두 캐시의 회계: 요청은 직전 요청의 캐시된 부분 이상을 읽고(\(a_r+w_r\le a_{r+1}\le L_r+o_r\)), 항상 올리는 \(s\)토큰은 \(s(\pi_w+(n-1)\pi_r)\)를 더하고, 위치 \(j\)의 변경은 \((L_{r-1}-j)(\pi_w-\pi_r)\)를 더 든다(). 9개 세션 기록의 2,283개 전이에서 낚아챈 15개는 모두 긴 간격이나 압축이었고, 나머지 2,268개에서 읽기는 직전 읽기와 직전 쓰기의 합(2,258개)이거나 거기에 직전 출력을 더한 값(10개)이었다. 입력의 98.7%가 캐시 읽기였다.
  4. 구성요소는 컨텍스트에 오르는 시점(매 요청, 세션 시작, 호출할 때, 이벤트마다, 올리지 않음)과 결정권(하네스, 모델, 사용자)으로 분류된다(). 첫 호출의 입력은 42,594토큰 이상이고 사용자 글은 1.39% 이하이다. 입력하기 전에 컨텍스트는 이미 하네스의 것이다.
  5. 하고 싶은 일은 금지, 의무, 선호로 나뉜다. 금지는 실행 길(deny 규칙, 실행 앞 hook, 샌드박스)이 규칙이 맞는 호출에 한해 보증하고, 글만 있으면 보증은 \(q^n\)이다. 하네스가 대신 할 수 있는 의무는 hook이 하고, 모델의 호출이 필요한 의무는 끝내는 지점의 검사로 확인하되 강제는 못 한다. 선호는 \(q\)가 곧 보증이다().
  6. 항상 올릴지 필요할 때 읽게 할지는 \(p^{*}=(s-d)K_1/(sK_k+mF)\)로 가른다. 토큰만 보면 필요할 때 읽는 쪽이 거의 항상 싸고, 항상 올리는 근거는 필요한 때 불러오지 못할 위험 \(mF\)이다(). 하위 에이전트는 비용을 없애지 않고 다른 컨텍스트로 옮기며 부모의 컨텍스트를 작게 남긴다.
  7. 이 장의 실험은 회계를 쟀지 Claude의 행동을 재지 않았다. 사전 예상 중 P1은 기각되었고(직전 응답의 출력이 다음 접두에 든다는 것을 빠뜨렸다) 정정은 결과를 본 뒤의 일이다. 실제 Claude Code를 돌리는 실험은 비용 때문에 슬롯으로 남겼다.

'규칙이 그 호출에 맞는 한'이라는 조건이다. 규칙은 Edit 도구의 호출에 맞춘 것이므로 셸 명령으로 낸 호출이 그 규칙에 맞는지는 별개이고, 맞지 않으면 실행 길이 막지 못한다. 문서는 Bash 규칙이 Claude가 쓴 명령의 글에 맞추므로 같은 프로그램을 다른 꼴로 부르면 비껴갈 수 있고, deny나 ask 규칙은 프로그램을 둘러싼 보안 경계가 아니라고 적는다. 이 간격은 24장의 샌드박스가 메운다. CLAUDE.md의 글은 읽기 길이어서 이 호출을 막지 못한다.

항목이 \(s=3000\), 설명이 \(d=100\)이고 \(n=50\), \(k=4\)이다. \(m=0.02\), \(F=40000\), \(\pi_w=1.25\), \(\pi_r=0.05\)이다. 손익분기 \(p^{*}\)를 구하고, 필요할 확률이 0.9와 0.95일 때 어느 쪽이 싼지 말하라.

풀이

에서 \(K_1=1.25+49\times0.05=3.7\), \(K_k=1.25+46\times0.05=3.55\)이다. 분자는 \((3000-100)\times3.7=10730\), 분모는 \(3000\times3.55+0.02\times40000=10650+800=11450\)이다. \(p^{*}=0.937\)이다. 0.9는 문턱 아래이므로 필요할 때 읽는 쪽이 싸고, 0.95는 문턱 위이므로 항상 올리는 쪽이 싸다. 놓칠 위험의 항 800이 없으면(\(mF=0\)) \(p^{*}=10730/10650=1.0075\)로 1을 넘어 필요할 때 읽는 쪽이 늘 싸다.

tiny17.py의 위임 설정(\(E=3000\), \(s=150\))에서 큰 읽기 뒤에 부모에 남는 요청 수를 \(m'\)이라 하자. 하위 에이전트 자신의 비용은 4,034.45이다. 부모의 절감이 \((E-s)(\pi_w+(m'-1)\pi_r)\)일 때, 부모의 절감에서 하위 에이전트의 비용을 뺀 순이득이 처음 양수가 되는 \(m'\)은? 그 값 이상에서 위임이 비용에서도 이득이라는 뜻인가?

풀이

절감은 \(2850\times(1.25+0.05(m'-1))=3562.5+142.5(m'-1)\)이다. \(m'=4\)이면 3,990이어서 \(-44.45\), \(m'=5\)이면 4,132.5이어서 \(+98.05\)이다. 처음 양수가 되는 값은 \(m'=5\)이다. 같은 값이 tiny17.py의 계획 길이를 바꿔 직접 돌려도 나온다(부모 안에서 읽을 때의 비용에서 위임한 부모의 비용과 하위 에이전트의 비용을 뺀 값). 그러나 이 계산은 토큰 값만 센 것이다. 부모의 컨텍스트가 작게 남는 이득(압축 간격, 희석)과 하위 에이전트가 요약을 잘못 만들 위험은 들어 있지 않다. 이 설정의 하위 에이전트는 큰 읽기 하나뿐이어서 \(m'\)이 작으면 손해이다.

풀이

기록이 독자마다 다르므로 정해진 답은 없다. 점검할 것은 이렇다. (1) 간격이 캐시 수명(5분 또는 1시간, 기록의 캐시 지점 설정에서 읽는다)을 넘었는지, 압축이 끼었는지 본다. 어느 것도 아닌 낚아챔이 있으면 모델 전환, 노력 수준 변경, MCP 서버의 연결과 제거 같은 접두 변경을 문서의 목록에서 찾아본다. 이 장의 기록에서는 일어나지 않아 시험하지 못한 경우이다. (2) 첫 호출의 길이는 독자의 skill, 에이전트, MCP, 지시 파일의 수에 따라 크게 다르다. 사용자 글의 몫의 상한은 거의 항상 몇 퍼센트 이하일 것이다. (3) 기록 형식이 버전에 따라 다르면 첨부의 이름이 다를 수 있다. 이 장의 기록은 2.1.319와 2.1.327이다. 사용량 세 숫자는 API가 정의한 필드이므로 버전이 달라도 읽을 수 있다.
